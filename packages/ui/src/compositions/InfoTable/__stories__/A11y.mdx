# InfoTable - Accessibility

## Description

A composition that displays key-value information (e.g. instance details, offer descriptions) as a grid of label/value pairs. It is built on the semantic HTML description list (`<dl>`), with each row rendered as a CSS-grid `<div>` and each cell containing a `<dt>` (title/label) and a `<dd>` (value). It supports an optional header that wraps the table in a `Card`, two sizes, and a `CellWithCopyButton` variant that embeds a `CopyButton` inside a cell.

## Summary

1. ❌ **Perceivable**: label/value association is not programmatically reliable because of invalid `<dl>` nesting
2. ✅ **Operable**: static content plus a native `<button>` (`CopyButton`) that is keyboard accessible with a visible focus indicator
3. ✅ **Understandable**: each cell `title` acts as a descriptive label for its value; a string `header` renders as an `<h2>`
4. ❌ **Robust**: invalid `<dl>` content model prevents description-list/term/description semantics from being reliably exposed; copy success feedback depends on the `CopyButton`/`Tooltip` strategy

## ARIA Pattern

There is no dedicated WAI-ARIA APG pattern for description lists; the native HTML `<dl>/<dt>/<dd>` semantics are the correct mechanism for key-value data and the component already targets them. For genuinely tabular data where row/column header relationships matter, see the [ARIA Table Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/).

## Rules

Enforced by the component:

- ❌ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The `<dl>` content model is invalid: each row is a `<div>` containing one `<div>` per cell that nests `<dt>`/`<dd>`. Per the HTML spec, a `<div>` inside a `<dl>` must directly contain the term/description group.
- ✅ [WCAG 1.4.3 - Contrast (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) - The `dt` term uses `prominence="weak"` (`theme.colors.neutral.textWeak`), which passes the 4.5:1 ratio on all themes (4.53 on light, 4.51 on dark, 4.5 on darker).
- ✅ [WCAG 1.4.4 - Resize Text (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) - Font sizes are in `rem`, so text scales with browser zoom and user font settings.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) and [WCAG 2.1.2 - No Keyboard Trap (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) - The only interactive element is `CopyButton`, a native `<button>`; focus moves freely in and out.
- ✅ [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) - Focus follows the visual reading order (rows top-to-bottom, cells left-to-right).
- ⚠️ [WCAG 2.4.6 - Headings and Labels (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) - A string `header` renders a hardcoded `<h2>` which might break page structure.
- ✅ [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) - `title` is a required prop and acts as the label for each value.
- ❌ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - Because of the invalid `<dl>` nesting, the description-list, term and description roles are not reliably exposed, and each value is not programmatically associated with its title.
- ⚠️ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) - The "Copied!" feedback of `CellWithCopyButton` depends on the `CopyButton`/`Tooltip` naming strategy (see the [CopyButton audit](https://storybook.ultraviolet.scaleway.com/?path=/docs/ui-action-copybutton-a11y--docs)).

To apply when using the component:

- [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) / [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) - When placing a `Status` or another colored indicator inside a cell, also provide text or a `tooltip` so the state is not conveyed by color alone.
- [WCAG 1.4.10 - Reflow (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) - Use responsive `templateColumns` values and avoid fixed `width` values; use `multiline` for long values so they wrap instead of truncating.
- [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) / [WCAG 2.4.6 - Headings and Labels (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) - When the `header` is a custom `ReactNode`, ensure it contains a proper heading element.
- [WCAG 1.4.4 - Resize Text (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) - `oneLine` truncation is acceptable only because the full content is available on hover/focus via tooltip, but prefer `multiline` for important values so nothing is hidden at large text sizes.

## Accessibility issues

**High:**

- Invalid `<dl>` content model: `dt`/`dd` are nested inside a second `<div>` (the `Stack`) below the row `<div>`. The HTML spec only allows `<dt>`/`<dd>` directly inside the `<dl>` or inside a single `<div>` wrapper that directly contains the term/description group. The extra nested `<div>` breaks the semantic association between each title and its value for assistive technologies (fails WCAG 1.3.1 and 4.1.2). Suggested fix: ensure there is at most one `<div>` wrapper between the `<dl>` and the `dt`/`dd` group, or make each row a direct child of the `<dl>` that directly contains the `dt`/`dd` pairs.

**Low:**

- Hardcoded `<h2>` for string headers: the heading level may skip a level depending on page structure. Consumers should not nest it in a way that breaks the heading order (WCAG 1.3.1 / 2.4.6).

## Dependencies

- `CopyButton` / `Tooltip`: the copy success announcement (WCAG 4.1.3) and the button accessible name depend on the strategies documented in the [CopyButton audit](https://storybook.ultraviolet.scaleway.com/?path=/docs/ui-action-copybutton-a11y--docs).
