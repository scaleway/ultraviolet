# CodeEditor - Accessibility

## Description

A code editor composition built on CodeMirror that lets developers write, edit and manage code. It wraps the editor with an optional label, helper/error description, copy button, line numbers, and an expandable/collapsible height feature. Supports disabled, readOnly, and required states.

## Summary

1. ❌ **Perceivable**: label not programmatically associated with the editor, gutter line numbers fail contrast (1.63:1), focus indicator fails contrast (1.44:1)
2. ❌ **Operable**: keyboard trap in the editor (Tab inserts tabulation with no way out), copy button unreachable by keyboard
3. ❌ **Understandable**: editor is not labeled (labels or instructions)
4. ❌ **Robust**: editor has no accessible name

## ARIA Pattern

There is no dedicated APG pattern for code editors. The closest reference is the [Textbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/textbox/) (multiline textbox), which CodeMirror follows by exposing the editor as a `role="textbox"` with `aria-multiline="true"`. The copy and expand/collapse controls follow the standard native [Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/) pattern.

## Rules

Enforced by the component:

- ✅ [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) - Icons inside the copy button are accompanied by text, and the arrow icon is decorative
- ❌ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The label is not programmatically associated with the editor: no `aria-labelledby`/`labelId` linking the label to the editor. The helper association via `aria-describedby` + helperId is correct.
- ⚠️ [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) - The disabled state is only conveyed by `aria-disabled` and color, the editor is not truly disabled (it remains focusable)
- ❌ [WCAG 1.4.3 - Contrast (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) - Gutter line numbers only reach a 1.63:1 contrast ratio (the rest of the text is fine)
- ❌ [WCAG 1.4.11 - Non-text Contrast (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) - The focus indicator box-shadow is only 1.44:1 against a white background
- ❌ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) - The copy button is inaccessible by keyboard (see the keyboard trap below)
- ❌ [WCAG 2.1.2 - No Keyboard Trap (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) - Once focus enters the editor, Tab is used to insert tabulation in the code and there is no key pairing to leave the editing state, so the focus is trapped
- ⚠️ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) - A focus indicator is shown but its contrast is too low (1.44:1, see 1.4.11)
- ✅ [WCAG 2.5.3 - Label in Name (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) - The visible text of the copy button matches its accessible name
- ✅ [WCAG 2.5.8 - Target Size (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) - The interactive controls have an adequate target size
- ❌ [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) - The editor is not labeled (see 1.3.1)
- ❌ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - The editor exposes a `textbox` role and its value is programmatically determined, but it has no accessible name
- ✅ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) - Helper and error messages are announced via `role="status"` and associated with `aria-describedby`

To apply when using the component:

- [WCAG 2.4.6 - Headings and Labels (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) - Consumers must provide a meaningful label describing the purpose of the editor. When used, the label, the helper, and the copy button content (if provided as a string) must each be exposed clearly to assistive technologies and their content must be clear.
- [WCAG 3.2.1 - On Focus (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html) - Consumers should ensure that focusing the editor or its buttons does not trigger a context change

## Accessibility issues

**Critical:**

- Keyboard trap (2.1.2): Tab is captured to insert tabulation inside the code, with no key pairing (e.g. `Ctrl/Cmd + Enter` or `Esc`) to leave the editing state. As a result, keyboard users cannot move focus to the copy button or beyond the editor (2.1.1).

**High:**

- No accessible name on the editor (4.1.2 / 1.3.1 / 3.3.2): the label is rendered as a sibling but is never associated with the editor through `aria-labelledby`/`labelId`, so assistive technologies expose an unnamed textbox. The `aria-label` is applied to the wrapper and not reliably propagated to the `role="textbox"` element, and it should be deprecated in favor of `accessibleLabel` (RFC #6585).
- Gutter line numbers contrast (1.4.3): the line number gutter only reaches a 1.63:1 contrast ratio.
- Focus indicator contrast (1.4.11 / 2.4.7): the focus box-shadow is only 1.44:1 against a white background.

**Medium:**

- Disabled state (1.4.1): the disabled state is conveyed with `aria-disabled` and color alone. The editor remains focusable and there is no textual indication of the disabled state, so it may not be perceived by all users.

**Low:**

- Add an `accessibleLabel` property to implement the chosen decision in [RFC #6585](https://github.com/scaleway/ultraviolet/discussions/6585), deprecate the `aria-label` property and use its value as a fallback for the `accessibleName`.
