# SelectInput - Accessibility

## Description

A combobox form control that lets users pick one or many options from a dropdown list. Supports search (fuzzy "smart" search and type-ahead "dumb" search), grouped options, multiselect with removable tags, "select all", dynamic "add option", lazy loading, tooltips, and error/success/helper states.

## Summary

1. ❌ **Perceivable**: single-select selected option is conveyed by background color only
2. ✅ **Operable**: single tab stop via roving focus (only the active option is `tabIndex={0}`); no keyboard trap; focus visible
3. ✅ **Understandable**: required state and error validity are surfaced on the control; search result count / empty state is announced via a live region.
4. ✅ **Robust**: accessible name via `aria-labelledby`; the popup is named by the same label; options named by their visible label; `aria-controls` points at the listbox with `aria-haspopup="listbox"`; unique ids; no nested interactive roles.

## ARIA Pattern

- [ARIA Combobox Pattern (select-only variant)](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
- [ARIA Listbox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/)

## Keyboard navigation & native `<select>` comparison

Native `<select>` has a single tab stop, Arrow/Home/End navigation, in-control type-ahead, and Escape closes with focus returning. The component matches on the key points:

- **Single tab stop**: only the active `role="option"` is `tabIndex={0}`, the rest are `-1`. Arrow up/down moves focus between options and back to the search bar.
- **No Home/End**: Arrow up/down only. Home/End is part of the APG Listbox keyboard model but not a WCAG failure — 2.1.1 is satisfied via Arrow keys. Optional.
- **Value change announced**: a live region announces the selected options (multiselect) and the search result count updates as you filter.

### "Dumb" search (non-searchable type-ahead)

Enabled when there is no search bar (`searchable=false`). `handleKeyDown` listens on `document` and moves focus to the first option matching typed characters. Inert while closed (popup only in the DOM when open). Notes:

- **Works only when not searchable**: the listener is attached only when `searchable === false`. When the "smart" search exists and its input is not focused, type-ahead does nothing. Either the search input should be focused, or the dumb select should be used.
- **Does not work while collapsed**: type-ahead is inert unless the dropdown is open (the popup `ref` is null while closed). Native `<select>` type-aheads even when collapsed (focused but closed), typing jumps the selection to the first matching option. Consider supporting type-ahead on the focused-but-closed select bar too.
- **Search buffer never resets while open**: `search`/`defaultSearch` only clear when the dropdown closes, with no timeout as in a native select. Successive characters accumulate indefinitely while open.
- **Modifier-key guard**: Ctrl/Cmd/Alt+char is not swallowed as type-ahead.

### "Smart" search (searchable)

Enabled automatically when `options.length >= 6` or `addOption` is set. The fuzzy `SearchBar` is a plain `TextInput` with `aria-label="search-bar"`. Notes:

- The typing input is a plain `TextInput`.
- Filtered results / "No options" empty state are announced via a `VisuallyHidden` `output` live region (`aria-live="polite"`, `aria-atomic`) wired with `aria-describedby` on the search bar (4.1.3).

## Rules

Enforced by the component:

- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html): single tab stop via roving focus; Escape closes and returns focus, the dropdown auto-closes on Tab-out.
- ✅ [WCAG 2.1.2 - No Keyboard Trap (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html): The popup does not trap focus.
- ✅ [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): roving focus keeps the tab sequence short.
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html): Relies on the default browser outline.
- ❌ [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): Single-select selected option is conveyed only by background color.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html): name via `aria-labelledby`; options named by label; `aria-controls` points at the listbox; unique IDs; no nested interactive roles.
- ✅ [WCAG 2.5.3 - Label in Name (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html): options/combobox named by their visible label; `aria-controls` points at the listbox.
- ✅ [WCAG 3.3.1 - Error Identification (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html): error text is associated via `aria-describedby` and `aria-invalid` is set on the control.
- ✅ [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html): `aria-required` surfaces requiredness.
- ✅ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): search result count / empty state is announced via a live region.

To apply when using the component:

- [WCAG 3.3.2 - Labels or Instructions (A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html): **do not rely on `placeholder`/`placeholderSearch` as a substitute for a visible `label`** — placeholder disappears when interacting and causes memory issues. Use it only as an example format.
- [WCAG 4.1.2 - Name, Role, Value (A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html): **always pass a `label`** (or `aria-labelledby`): without it the combobox has no accessible name.
- [WCAG 1.1.1 - Non-text Content (A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html): icons used inside labels/options are hidden by default (Icons `aria-hidden`); when an icon is informative, provide a text alternative or tooltip.
- **External `Label`/`Description`**: if rendered outside the component's built-in props, manage associations yourself: `Label` `htmlFor`/`aria-labelledby` matching the combobox id, and the `Description` id in `aria-describedby`.

## Past accessibility issues

<details>
  <summary>Past accessibility issues</summary>

**Critical:**

- ✅ **Options are named by `option.value`, not the visible label**:
  - `aria-label={option.value}` overrode the label text (which may be a `ReactNode` or differ from the value), so screen readers announced the raw value (2.5.3, 4.1.2).
  - **Resolved** by removing `aria-label` from the option; the visible label now computes the name.
- ✅ **`aria-controls` points at the popup, not the listbox**:
  - It referenced the popup element carrying `role="dialog"` instead of the `role="listbox"`; `aria-haspopup` was missing.
  - **Resolved** by pointing `aria-controls` at the listbox id and adding `aria-haspopup="listbox"` via `Popup.Trigger`, and extending `Popup.Trigger` to accept/forward `aria-controls` and `aria-haspopup` overrides.
- ✅ **No accessible name without a `label` prop**:
  - The name relied solely on `aria-label={label}`, and the `Label htmlFor` targeted a `<div>`, which is not a labelable element.
  - **Resolved** by naming the combobox through `aria-labelledby` referencing the `Label`'s id, and rendering the `accessibleLabel` in a `VisuallyHidden` `<label>` when no `label` is provided.

**High:**

- ✅ **Duplicate IDs**:
  - `id="option-{indexOption}"` was group-local and `id="items"` was repeated, breaking `getElementById`, associations, and assistive technology.
  - **Resolved** by using `useId()` per option and querying enabled `role="option"` elements within the listbox.
- ✅ **Every option is a tab stop**:
  - All options were `tabIndex={0}`, producing a long tab sequence and leaving the dropdown open while focus moved on.
  - **Resolved** with a roving tabindex. Only the active option is `tabIndex={0}`, others `-1`.
- ✅ **Selection change is not announced**:
  - The combobox name overrode the inner value text and there was no live region.
  - **Resolved** for multiselect with a live region announcing the selected options. Single-select announcement was reviewed and deemed a false positive.

**Medium:**

- ✅ **No `aria-invalid` / `aria-required`** on the combobox:
  - Error/requiredness were not programmatically determinable.
  - **Resolved** by setting `aria-invalid={!!error}` and `aria-required={required}` on the combobox.
- ✅ **"Select group" button is not reachable via Arrow up/down**:
  - The arrow-navigation selector originally skipped the group selector.
  - **Resolved** by rendering selectable group headings as listbox options that match `OPTION_SELECTOR`.
- ✅ **Search input is not an ARIA combobox, no `aria-activedescendant`**:
  - Typing gave no announced "active option" and the empty state was not announced.
  - **Partially resolved**: the result count / empty state is now announced via a live region wired with `aria-describedby``aria-activedescendant` is intentionally not applied — it breaks focus management.
- ✅ **Nested interactive roles**:
  - `role="option"` contained a `role="checkbox"` and a `<button>` wrapped a `<Checkbox>`.
  - **Resolved** by hiding the checkbox inputs and representing selectable groups as listbox options.
- ✅ **Non-actionable group `<button>`**:
  - When `selectAllGroup` is false it rendered a `<button tabIndex={-1}>` that did nothing.
  - **Resolved** by rendering a plain `<div>` when not selectable.
- ✅ **In a Modal, Escape closes the modal instead of the dropdown**:
  - The Modal's Escape handler won over the `Popup`'s, dismissing the whole modal instead of first closing the dropdown.
  - **Resolved**: Escape closes only the dropdown (Popup capture-phase handler).

**Low:**

- ⚠️ **No Home/End**:
  - Recommended by the Listbox APG but not a WCAG failure; optional, not implemented.
- ✅ **Search bar autofocus**:
  - Focus moved to the search input 50ms after open.
  - **Resolved**: in order of importance and, if present, focus moves to the search bar, the first selected element, then the first element.
- ✅ **"Dumb" search modifier keys**:
  - Browser shortcuts while open were swallowed as type-ahead.
  - **Resolved** by adding a `ctrlKey/metaKey/altKey` guard.

</details>

## Dependencies

- **Popup**: `Popup.Trigger` accepts `aria-controls` and `aria-haspopup` overrides; SelectInput points them at the listbox. The popup panel carries a labelled `role="dialog"`, while its listbox contains options and named groups.
- **Tooltip**: hover/focus behavior on options and the select bar.
- **Description**: error/success/helper uses `role="status"`; error messages ideally announced with an assertive role.
- **Modal**: its Escape handler intercepts Escape before the `Popup`, closing the modal instead of the dropdown (resolved — Escape closes only the dropdown).
- **Icons**: once all icons are `aria-hidden` by default (per team standard), the decorative arrow/error/success icons resolve.
