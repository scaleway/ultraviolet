# VerificationCode - Accessibility

## Description

An OTP (one-time password) / verification code input rendered as a single field, visually split into several input boxes (4 by default). Typing, Backspace, Arrow keys and paste are handled natively by the input. Supports an optional label and helper/error/success text.

## Summary

1. ✅ **Perceivable**: the code is entered in a single field, visually split into boxes. The boxes are `aria-hidden` and a real `<label>` (visible or `VisuallyHidden`) provides the accessible name, so the whole code is announced as one field. `autocomplete="one-time-code"` enables OTP autofill (WCAG 1.3.5).
2. ✅ **Operable**: fully keyboard operable (typing, Backspace, Arrow keys, paste) with a visible focus indicator on the active box.
3. ✅ **Understandable**: labels come from the visible `label` or the `accessibleLabel` prop; the deprecated `aria-label` is kept only as a fallback.
4. ✅ **Robust**: a single field with an accessible name, role and value.

## Rules

Enforced by the component:

- ✅ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The code is a single field labelled by a real `<label>` (visible or `VisuallyHidden`); the visual boxes are `aria-hidden`, so the field is announced as one unit.
- ✅ [WCAG 1.3.5 - Identify Input Purpose (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html) - `autoComplete="one-time-code"` declares the input purpose and enables OTP autofill.
- ✅ [WCAG 2.4.6 - Headings and Labels (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) - the field's accessible name is derived from the visible label / `accessibleLabel`, matching the label shown to users.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) - A single native text input, fully keyboard operable.
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) - A focus box-shadow indicator is applied to the active box.
- ✅ [WCAG 3.3.1 - Error Identification (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html) - Error text is displayed and associated via `aria-invalid` / `aria-describedby`.
- ✅ [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) - A visible label and/or accessible name is provided.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - The field has an accessible name, an implicit textbox role and a value.
- ✅ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) - Helper/error/success text is exposed through `role="status"` in `Description`.
- ✅ [RFC #6585 - Accessible Icons and Hidden Labels](https://github.com/scaleway/ultraviolet/discussions/6585) - The component now exposes an `accessibleLabel` prop rendered as a `VisuallyHidden` label, replacing the deprecated `aria-label` pattern.

To apply when using the component:

- [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) - Error/success must also be conveyed through text (the `Description`), not only border color, when displayed.
- [WCAG 3.3.3 - Error Suggestion (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html) - Provide guidance in the helper about the expected code format (e.g. number of digits) when relevant.

<summary>Past accessibility issues</summary>

**Critical:**

- ✅ **Multiple separate fields instead of a single field.**
  - The multi-input approach forced screen reader users to tab through and interpret several "Verification code 0/1/2/3" textboxes, and complicated paste and autofill.
  - **Resolved** by rendering a single real `<input>` overlaid on N visual boxes (`aria-hidden`), so assistive technologies interact with one field and the boxes are purely visual.

**High:**

- ✅ **`autoComplete="off"` blocks OTP autofill**
  - Failed to declare the input purpose, preventing mobile browsers from auto-filling a one-time code.
  - **Resolved** by setting `autoComplete="one-time-code"` on the field.
- ✅ **Missing `<legend>` in the `<fieldset>`**
  - The group of fields had no programmatic name so it was not announced as a single logical unit.
  - **Resolved** by moving to a single field named by a real `<label>` (visible or `VisuallyHidden`), so no group/legend is needed.
- ✅ **Uses deprecated `aria-label` pattern**
  - Per [RFC #6585](https://github.com/scaleway/ultraviolet/discussions/6585), should migrate to an `accessibleLabel` prop (a hidden label rendered via `VisuallyHidden`).
  - **Resolved** by adding the `accessibleLabel` prop; `aria-label` is deprecated but kept as a fallback (`index.tsx`).
- ✅ **Hardcoded default `aria-label` overrides the visible label**
  - A default `aria-label` was always applied to every box and took precedence over the visible `<label>`.
  - **Resolved** by removing the hardcoded default; the accessible name now comes from the visible label, the `accessibleLabel` or the deprecated `aria-label`.
- ✅ **Missing `aria-labelledby`**
  - The visible `<label>` was only linked to the first box via its `htmlFor`, and was overridden by the always-present `aria-label`.
  - **Resolved** by labelling the single field with the visible `<label>` (via `htmlFor`) or a `VisuallyHidden` label, and hiding the visual boxes from the accessibility tree.

**Medium:**

- ✅ **No `inputmode="numeric"`**
  - Relied on `type="tel"` instead of showing the numeric keypad reliably.
  - **Resolved** by using `type="text"` with `inputmode="numeric"` for numeric codes.
- ✅ **Verbose screen-reader naming**
  - Announcing "Verification code 0", "Verification code 1", ... for each box was noisy.
  - **Resolved** by exposing a single field announced once with its real label; the boxes are `aria-hidden`.
