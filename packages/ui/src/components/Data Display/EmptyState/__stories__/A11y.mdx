# EmptyState - Accessibility

## Description

A layout/presentation component that displays a message when there is no data to show. It renders an optional image, an optional title, a description, optional action buttons, an optional "learn more" link, and custom children.

## Summary

1. ⚠️ **Perceivable**: text is readable and contrasted, but the image `alt` and heading semantics depend on usage; the heading level is hard-coded.
2. ✅ **Operable**: all interactive elements are delegated to accessible `Button`/`Link` components; content scales with text resizing.
3. ✅ **Understandable**: content is plain text with descriptive title and description.
4. ✅ **Robust**: uses native HTML semantics (`h2`, `p`, `div`) and delegates interactive controls to their own accessible components.

## ARIA Pattern

No specific WAI-ARIA Authoring Practices pattern exists for an "empty state". It is a generic content container; interactive controls inside it (buttons, links) follow their own patterns.

## Rules

Enforced by the component:

- ⚠️ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The title is always rendered as an `<h2>`. The heading level cannot be customized, so it may break the document outline depending on where the component is used.
- ✅ [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) - String images are rendered with `alt=""` (decorative), so they are ignored by assistive technology. Component-provided images are expected to be decorative.

To apply when using the component:

- [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html) - If a component-based image conveys meaning, provide an accessible name (`alt`, `aria-label`, or title) on that image. Decorative images should be hidden from assistive technology (`alt=""`).
- [WCAG 2.4.4 - Link Purpose (In Context) (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/link-purpose-in-context.html) - The `learnMore` link text should describe its destination.
- [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - Interactive controls passed as `primaryButton`/`secondaryButton`/`learnMore` must have accessible names.

## Accessibility issues

**High:**

- The `title` is always rendered as `<h2>`. There is no way to specify a different heading level, so using the component multiple times on a page or in a nested context can produce an incorrect heading outline, violating 1.3.1.

**Medium:**

- When `image` is a string it is always rendered with `alt=""`. This is correct for decorative images but provides no way to supply meaningful alternative text if the image conveys information.

## Dependencies

- `Button` and `Link` components must remain accessible for the `primaryButton`, `secondaryButton`, and `learnMore` slots to work.
