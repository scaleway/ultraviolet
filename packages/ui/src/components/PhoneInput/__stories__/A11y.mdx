# PhoneInput - Accessibility

## Description

A form input component for entering and validating international phone numbers. Features country flag display, automatic phone number formatting, validation with error/success states, and support for controlled/uncontrolled modes.

## Summary

1. ⚠️ **Perceivable**: Proper labeling and error states, but flag emoji lacks text alternative
2. ✅ **Operable**: Native input element with standard keyboard support
3. ⚠️ **Understandable**: Uses deprecated `aria-label` pattern
4. ✅ **Robust**: Correct ARIA attributes and native HTML semantics

## Rules

Enforced by the component:

- ✅ [WCAG 3.3.1 - Error Identification (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html): Error state is identified with `aria-invalid` and error message is associated via `aria-describedby`
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html): Uses native `<input type="tel">` with proper label association and ARIA attributes
- ✅ [WCAG 2.4.6 - Headings and Labels (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html): Label component properly associated with input via `htmlFor`
- ✅ [WCAG 1.4.11 - Non-text Contrast (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html): Error and success icons use sentiment colors with enough contrast
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html): Input has native focus indicator with sufficient contrast
- ❌ [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html): Country flag emoji lacks `aria-hidden` and `accessibleName` with country name
- ⚠️ [RFC #6585 - Accessible Icons and Hidden Labels](https://github.com/scaleway/ultraviolet/discussions/6585): Component uses deprecated `aria-label` pattern. Should migrate to `accessibleLabel` prop (for hidden labels) per new team standards

To apply when using the component:

- [WCAG 1.3.5 - Identify Input Purpose (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/identify-input-purpose.html): Add `autocomplete="tel"` when collecting user's phone number
- [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html): Provide helper text with expected phone number format
- [WCAG 3.3.3 - Error Suggestion (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/error-suggestion.html): Provide format suggestions in error messages (e.g., "Enter phone number in international format: +1 234 567 8900")
- [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html): **Do not use `placeholder` as a substitute for visible `label`**. Use placeholder for example input format only, not as the primary label
- **When using external `Label` or `Decription` components**: If you render `Label` and/or `Description` (for helper/error/success messages) externally instead of using the built-in props, you **must** manually manage ARIA associations:
  - Ensure `Label` has a `htmlFor` attribute matching the input's `id`
  - Pass the `Description` component's `id` to the input's `aria-describedby` prop

## Accessibility issues

**High:**

- Flag emoji lacks accessible name - The country flag emoji (`getPhoneCountryFlag(countryFlag)`) is decorative but conveys meaningful information (selected country). Screen readers may announce emoji flags inconsistently. Should add `aria-hidden` and accessible label (via `VisuallyHidden` component) with the country name.

**Medium:**

- Missing `autocomplete="tel"` attribute - The component should support an `autocomplete` prop to allow developers to specify `autocomplete="tel"` for better form autofill support. This helps users with cognitive disabilities by reducing manual input.
- Uses deprecated `aria-label` pattern. Per [RFC #6585](https://github.com/scaleway/ultraviolet/discussions/6585), should migrate to `accessibleLabel` prop for hidden labels. Current `aria-label` prop should be deprecated in favor of the new pattern.
- Uses deprecated `tooltip` prop instead of `tooltipDescription`.

## Dependencies

- Description component should have appropriate aria attributes for status messages
- Tooltip component must be accessible to keyboard and screen reader users
- Migration depends on RFC #6585 implementation: `accessibleLabel`, `tooltipDescription` props and `VisuallyHidden` component
