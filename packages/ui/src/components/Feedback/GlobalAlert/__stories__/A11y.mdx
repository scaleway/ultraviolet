# GlobalAlert - Accessibility

## Description

A persistent, full-width feedback bar displayed at the top of a page to draw attention to a site-level announcement. It supports three variants (`info`, `danger`, `promotional`), an optional action button, an optional close button, and an embedded link sub-component. It manages its own open/closed state internally.

## Summary

1. ✅ **Perceivable**: correct color contrast and text presentation across all variants
2. ⚠️ **Operable**: native `<Button>` and `<Link>` elements are keyboard accessible, but focus is lost when the alert is dismissed
3. ✅ **Understandable**: content is readable and no change of context is triggered on focus or input
4. ❌ **Robust**: missing `role` on the container and the close button has no accessible name

## ARIA Pattern

[ARIA Alert Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/)

The pattern requires a `role="alert"` on the widget container so that dynamically rendered alerts are automatically announced by screen readers. The pattern also specifies that alerts must not require focus to be moved to them (the [Alert Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) is only for situations where interrupting the workflow is necessary). The [Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) also applies to the close and action buttons.

## Rules

Enforced by the component:

- ✅ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The message is rendered as a paragraph (`<Text as="p">`) and the embeddable link as a native `<a>`, preserving the visual reading order.
- ✅ [WCAG 1.4.3 - Contrast (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) - White text on the `promotional` variant does not sit on the lightest area of the aqua gradient, so the contrast requirement is met for the `bodySmall` text.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) - The action button and close button use the native `<Button>` component and the link uses the native `<Link>` (anchor), all fully operable from the keyboard (Tab to move, Enter/Space to activate, Enter to follow links).
- ✅ [WCAG 2.1.2 - No Keyboard Trap (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) - Focus can move in and out of the alert freely.
- ✅ [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) - Focus order follows the visual reading order: message content, action button, close button.
- ⚠️ [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) - When the alert is dismissed, the whole component is unmounted and focus is lost rather than redirected to a logical element.
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) - The native `<Button>` component provides a visible focus indicator; the close-button style only strips the background on focus, not the outline.
- ✅ [WCAG 3.2.1 - On Focus (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html) - Receiving focus does not trigger any change of context.
- ✅ [WCAG 3.2.2 - On Input (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html) - No change of context is triggered by user input.
- ❌ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - The alert container has no `role` attribute, preventing assistive technologies from identifying it as an alert. The close button also has no accessible name, as its only content is the `CloseIcon` which is decorative (`aria-hidden="true"`).
- ❌ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) - The alert lacks `role="alert"` (or `role="status"`), so status messages cannot be programmatically determined and announced by assistive technologies when dynamically inserted.

To apply when using the component:

- [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) - The variant is conveyed only through the background color (there is no icon, unlike the `Alert` component). Ensure the message content itself (e.g., "Warning: ...", "Your trial has expired") carries the meaning so it is not dependent on color alone.
- [WCAG 2.5.3 - Label in Name (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) - Visible text within the alert (message or action button label) should match the accessible name of the corresponding controls.

## Accessibility issues

**Critical:**

- Close button has no accessible name (`index.tsx:66-79`). The close `<Button>` contains only `<CloseIcon />`, which renders an `aria-hidden="true"` SVG and provides no accessible name. Unlike the sibling `Alert` component, which passes `accessibleLabel="close"`, the component is announced as an unlabeled "button". This directly fails WCAG 4.1.2.

- Missing `role="alert"` on the alert container (`Stack` in `index.tsx:47`). Screen readers will not announce the alert when it is dynamically inserted into the page. This is the core requirement of the [ARIA Alert Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/) and a direct failure of WCAG 4.1.2 and 4.1.3.

**High:**

- No focus management on dismiss. When the close button is activated (`index.tsx:69-72`), the component returns `null` and focus is lost. Keyboard and screen reader users who dismiss the alert may lose their place in the page. Focus should be redirected to a logical element (e.g., the element that triggered or follows the alert).

**Medium:**

- The variant is conveyed only through color. There is no icon or text prefix indicating the variant/severity, and the variant attribute (`data-variant`) is not exposed to assistive technologies. Screen reader users cannot distinguish `danger` from `info`/`promotional` beyond the content they write themselves (WCAG 1.4.1).

- Consider using `role="status"` instead of `role="alert"` for non-critical variants (`info`, `promotional`). `role="alert"` is assertive and interrupts the user, while `role="status"` is polite and more appropriate for non-critical announcements. This could be tied to the `variant` prop (e.g., `danger` uses `alert`, others use `status`).

**Low:**

- The close button's accessible name (once added) should be descriptive, since "close" alone is generic when multiple alerts are displayed on the same page. Consider deriving the label from the message content (e.g., `Close {message} alert`).
