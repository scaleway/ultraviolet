# Tag - Accessibility

## Description

A metadata component that displays a short text description of an item (category, label, key-value). It supports several variants: `copiable` (renders a button that copies its text to the clipboard), `closable` (renders a close button via `onClose`), `disabled`, `isLoading`, and a `keyValue` layout, all available in 7 color sentiments.

## Summary

1. ✅ **Perceivable**: decorative icons are `aria-hidden` (resolved by the Icon component fix); sentiment contrast is correct.
2. ✅ **Operable**: the disabled copiable button remains focusable even though it performs no action.
3. ✅ **Understandable**: the copiable button lacks `type="button"` and may unexpectedly submit a parent form.
4. ✅ **Robust**: the "Copied!" status message is announced via a `role="status"` live region (4.1.3).

## Rules

Enforced by the component:

- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - A non-copiable tag renders as a `<span>` and a copiable/removable tag uses a native `<button>`.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) - The copiable button in a `disabled` state is not keyboard-focusable and doesn't perform any action.
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) - Both the **copiable** button and the **close (closable)** button keep the browser-default focus ring, which is a valid, visible focus indicator (passes).
- ✅ [WCAG 3.2.2 - On Input (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html) - The copiable `<button>` has `type="button"` attribute.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - The removable (close) button's has an explicit label that includes the visible tag text.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - The copiable button's accessible name is the tag text, and the tooltip is wired as its accessible description. On focus, the action is conveyed as a description, so the button's purpose is programmatically determinable.
- ✅ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) - The "Copied!" feedback is announced to screen readers through a visually hidden `role="status"` live region rendered for copiable tags.
- ⚠️ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - When `isLoading` is combined with `copiable`, the loader's `role="progressbar"` is exposed inside the button so screen reader users know the tag is loading (same pattern as `Button`). However it also announces its `aria-valuenow`/`aria-valuetext` ("20%"), which is noisy for an indeterminate loader. **Open** — the `Loader` component should be updated so an indeterminate loader announces only its label (no percentage).

To apply when using the component:

- [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) - The `sentiment` is conveyed only through color; ensure the meaning is also present in the tag text where the sentiment carries information.
- [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) - On tag removal, focus should be repositioned to a relevant location. `onClose` is external, so this is the consumer's responsibility.

## Accessibility issue

⚠️ Loader inside a copiable button:

- `isLoading` renders a `role="progressbar"` labeled "Loading" inside the button. The progressbar announces its percentage ("Loading 20%"), which is noise for an indeterminate loader. The `Loader` component should be updated so an indeterminate loader announces only its label; tracked for a future `Loader` change.

<details>
  <summary>Past accessibility issues</summary>

**High:**

- ✅ Missing `type="button"` on the copiable button:
  - `TagInner` now renders `<button>` _with_ `type="button"`. Inside a form, clicking a copiable Tag will not submit the form unexpectedly (WCAG 3.2.2).
- ✅ When `copiable` and `disabled` are both set, the element renders as a `<button>` with the `disabled` attribute:
  - Disabled copiable tags are now programmatically disabled, so they do not remain in the tab order and are announced as a disabled button.
- ✅`aria-disabled` is applied to the inner text `<span>`, not to the interactive copiable button:
  - Removed `aria-disabled` since `disabled` is already set on the button.
- ✅ Close label:
  - Removed `aria-label="Close tag"` and instead use accessibleLabel on Icon. A removable tag's button label contains the visible tag label (e.g. `Remove {label}`) so screen reader users know which tag they are removing.
- ✅ Copy success is not announced to screen readers:
  - The "Copied!" feedback was only shown through a Tooltip (`role="tooltip"`), which is not read by screen readers, so screen reader users got no confirmation the copy succeeded (WCAG 4.1.3). Resolved by rendering a visually hidden `role="status"` live region for copiable tags that announces the `copiedText`.

**Low:**

- ✅ KeyValue separator hidden
  - the vertical `<Separator>` between key and value is presentational; a `aria-hidden` was added so it is not announced.

## Dependencies

- `Icon` - Icons (CloseIcon, CopyContentIcon, and child icons) are `aria-hidden` by default
- `Tooltip` - The copy-feedback mechanism relies on tooltip announcement behavior.
- `Loader` - When `isLoading` is combined with `copiable`, the loader's `role="progressbar"` is exposed inside the button so the loading state is announced. Its `aria-valuenow`/`aria-valuetext` ("20%") is noisy for an indeterminate loader and should be dropped in a future `Loader` update.
