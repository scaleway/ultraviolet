# Tooltip - Accessibility

## Description

A component that displays additional information related to an element when the element receives keyboard focus or mouse hover. It is built on `@floating-ui/react` with `role="tooltip"` and supports placement, max width, open/close delays, controlled visibility, and portal rendering.

## Summary

1. ✅ **Perceivable**: Tooltip is hoverable (`safePolygon` keeps it open when the cursor moves onto it). The relationship between trigger and tooltip is conveyed via `aria-describedby` (or `aria-labelledby` when `relation="label"`). Label tooltips are always rendered in the DOM (visually hidden until interaction) so the accessible name is immediately available. Description tooltips are only rendered on hover/focus for performance on large pages; `aria-describedby` is set at that point to avoid referencing a non-existent element.
2. ✅ **Operable**: The wrapping `div` no longer adds `tabIndex` when the children already contain a focusable element. Escape dismisses the tooltip and focus stays on the trigger.
3. ✅ **Understandable**: Content is readable and appears/disappears on focus/blur as expected.
4. ✅ **Robust**: `aria-describedby` (or `aria-labelledby`) is forwarded to function children render props. `role="tooltip"` is hardcoded on the tooltip element.

## ARIA Pattern

[Tooltip Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)

Key requirements from the pattern:

- The tooltip container has `role="tooltip"`.
- The trigger element references the tooltip with `aria-describedby`.
- Tooltips do not receive focus.
- Escape dismisses the tooltip.
- Focus stays on the triggering element while the tooltip is displayed.

## Rules

Enforced by the component:

- ✅ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The wrapping `div` correctly sets `aria-describedby` (or `aria-labelledby` when `relation="label"`) to associate the trigger with the tooltip. Function children receive the same attributes via render props.
- ✅ [WCAG 1.4.3 - Contrast (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) - White text (`#ffffff`) on dark navy background (`#151a2d`) provides well above 4.5:1 contrast.
- ✅ [WCAG 1.4.4 - Resize Text (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) - Uses `rem` units so text scales with user font size settings.
- ✅ [WCAG 1.4.13 - Content on Hover or Focus (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) - The tooltip is dismissible (Escape), persistent, and hoverable: `safePolygon()` in `useHover` keeps the tooltip open while the cursor travels between trigger and tooltip, and `pointer-events` is no longer disabled on the tooltip element.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) - Tooltip appears on keyboard focus and can be dismissed with Escape.
- ✅ [WCAG 2.1.2 - No Keyboard Trap (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/no-keyboard-trap.html) - Focus is not trapped; Tab moves freely and Escape dismisses the tooltip.
- ✅ [WCAG 2.4.11 - Focus Not Obscured (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured.html) - The `flip()` and `shift()` middlewares help keep the tooltip visible in all conditions.
- ✅ [WCAG 2.5.1 - Pointer Gestures (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html) - Only simple hover/focus is required; no multi-point or path-based gestures.
- ✅ [WCAG 3.2.1 - On Focus (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/on-focus.html) - No unexpected context change when the trigger receives focus.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - `role="tooltip"` is hardcoded on the tooltip element. `aria-describedby` (or `aria-labelledby` when `relation="label"`) is forwarded to both ReactNode and function children render props.

To apply when using the component:

- [WCAG 2.4.3 - Focus Order (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) - When children is already a focusable element (e.g., `Button`, `a`), prefer function children or pass `tabIndex={-1}` on the wrapper to avoid creating a double tab stop.
- [WCAG 2.4.11 - Focus Not Obscured (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured.html) - Choose a `placement` that does not obscure the trigger or other focused content in the viewport.

<details>
  <summary>Past accessibility issues</summary>

**Critical:**

- ✅ Missing `aria-describedby` when using function children

  <details>
    <summary>Resolved</summary>
    The `TooltipChildren` component now forwards `aria-describedby` (or `aria-labelledby` when `relation="label"`) to
    the function children render props, alongside the event handlers and `ref`. Screen readers can now programmatically
    associate the trigger with the tooltip content.
  </details>

**High:**

- ✅ Tooltip is not hoverable (`pointer-events: none`)

  <details>
    <summary>Resolved</summary>
    `pointer-events: none` has been removed from the tooltip styles. The `useTooltip` hook now uses `useHover` with
    `safePolygon()` from `@floating-ui/react`, which keeps the tooltip open while the cursor travels between the trigger
    and the tooltip element.
  </details>

- ✅ Extra tab stop when children is focusable

  <details>
    <summary>Resolved</summary>
    `TooltipChildren` now queries for a focusable element inside the wrapper. If one is found, the wrapper's `tabIndex`
    is left untouched (the focusable child receives focus instead). The `tabIndex` prop is only applied to the wrapper
    when no focusable child exists.
  </details>

**Medium:**

- ✅ `aria-controls` is incorrectly set on the trigger

  <details>
    <summary>Resolved</summary>
    The Tooltip no longer wraps the `Popup` component. It uses `@floating-ui/react` directly, whose
    `getReferenceProps()` does not add `aria-controls` for tooltips. The WAI-ARIA tooltip pattern only requires
    `aria-describedby`.
  </details>

- ✅ Debounce delay may cause race condition with screen readers

  <details>
    <summary>Resolved</summary>
    The tooltip element is now displayed immediately when using the keyboard.
  </details>

- ✅ `role` is overridable

  <details>
    <summary>Resolved</summary>
    The `role` prop is deprecated and no longer forwarded to the tooltip element. `role="tooltip"` is hardcoded in
    `TooltipElement.tsx`, preventing consumers from accidentally breaking tooltip semantics.
  </details>

- ✅ The Tooltip doesn't allow to be linked as a label using the `aria-labelledby` attribute instead of `aria-describedby`.

  <details>
    <summary>Resolved</summary>A new `relation` prop (`"description"` | `"label"`) controls whether the trigger is
    associated with the tooltip via `aria-describedby` (default) or `aria-labelledby`. The latter is useful for
    icon-only buttons that need an accessible name.
  </details>

- ⚠️ The Tooltip content is initially not rendered in the page

  <details>
    <summary>Resolved for label tooltips</summary>
    Label tooltips (`relation="label"`) are now always rendered in the DOM, visually hidden until the trigger is hovered
    or focused. This makes the accessible name immediately available to screen readers and bots without requiring
    interaction. The `visuallyHidden` style is applied while the tooltip is not mounted, and removed once the user
    hovers/focuses the trigger so the tooltip becomes visible at its floating position.
    <br />
    Description tooltips (`relation="description"`, the default) are only rendered into the DOM when the trigger is
    hovered or focused. This is an intentional tradeoff to avoid flooding the DOM on large pages that may contain many
    description tooltips. The WAI-ARIA tooltip pattern allows this behaviour, and `aria-describedby` is only set once
    the tooltip element exists to avoid referencing a non-existent element. If immediate availability is required, use
    `relation="label"` or set `delay={{ open: 0 }}`.
  </details>

**Low:**

- ⚠️ Tooltip font size is `0.75rem` (12px, `caption` typography) - Relatively small; may be harder to read for users with low vision, though it does scale with `rem`.

</details>

## Dependencies

None. The Tooltip has been refactored to use `@floating-ui/react` directly instead of wrapping the `Popup` component. All accessibility-relevant logic now lives in the Tooltip component itself (`useTooltip.ts`, `TooltipChildren.tsx`, `TooltipElement.tsx`).
