# CopyButton - Accessibility

## Description

A button that copies a given value to the clipboard. It renders as a native `<button>` (via the shared `Button` component) with a copy icon and, optionally, text children. Its accessible name and success feedback are both driven by a tooltip label that switches from "Copy" to "Copied!" (with a checkmark icon) for 2.5 seconds after activation.

## Summary

1. ✅ **Perceivable**: Icons are `aria-hidden` by default; color is not the only indicator of state (icon + label change together)
2. ✅ **Operable**: Native `<button>` with full keyboard support (Enter, Space) and visible focus indicator
3. ⚠️ **Understandable**: When `children` text is provided, the tooltip label overrides the visible text as the accessible name, so the announced name differs from what is seen
4. ❌ **Robust**: Copy success/failure is not announced to assistive technologies (no status message)

## ARIA Pattern

[ARIA Button Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)

## Rules

Enforced by the component:

- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html): Renders a semantic native `<button>`; the accessible name is provided via `aria-labelledby` pointing to the tooltip label ("Copy" / "Copied!"). Even in icon-only mode the button has an accessible name.
- ❌ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html): When `children` text is provided (e.g., "Copy id"), the tooltip label ("Copy") is applied via `aria-labelledby` (relation `label`), which overrides the visible text as the accessible name. The announced name therefore differs from the visible label.
- ✅ [WCAG 2.1.1 - Keyboard (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html): Native button activation with Enter and Space.
- ✅ [WCAG 2.4.7 - Focus Visible (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html): Native focus ring preserved by the `Button` component.
- ✅ [WCAG 1.1.1 - Non-text Content (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html): Icons (`CopyContentIcon`/`CheckIcon`) default to `aria-hidden="true"` and are purely decorative; the state is conveyed by the label.
- ❌ [WCAG 4.1.3 - Status Messages (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): The success feedback ("Copied!") is communicated only by changing the button's accessible name — there is no `role="status"` or live region, so the outcome is not announced to screen reader users.

To apply when using the component:

- [WCAG 3.2.4 - Consistent Identification (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html): Keep the announced accessible name aligned with the visible label.

## Accessibility issues

**High:**

- No success/status announcement. After activating the button, the "Copied!" confirmation is conveyed only by swapping the accessible name and icon. Screen reader users receive no announcement that the copy succeeded, because the change is not exposed through a live region or `role="status"`. Consider adding an `aria-live`/`role="status"` region (e.g., a visually hidden status element) that announces the copy result on activation.
- Accessible name overrides visible text when `children` is used. Because `tooltipLabel` maps to `relation="label"`, the tooltip text becomes the accessible name via `aria-labelledby`, so a button showing "Copy id" is announced as "Copy". Fix: switch between the two tooltip props depending on `children`: use `tooltipDescription` when there is `children` (so the visible text remains the accessible name), and use `tooltipLabel` when there is no `children` (so the icon-only button still has an accessible name).

**Medium:**

- Copy failures are silently swallowed (`catch(() => null)`). If the clipboard write fails, there is no feedback at all, so users cannot tell the action did not succeed. Expose the failure through a status message as well.

## Dependencies

- `Button` component: provides the native button, focus management, icon handling, and tooltip `aria-labelledby` wiring as well as styling.
- `Tooltip` component: supplies the accessible name via `aria-labelledby` (relation `label`).
