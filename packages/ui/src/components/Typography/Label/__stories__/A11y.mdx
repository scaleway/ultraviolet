# Label - Accessibility

## Description

A typography component that renders a native `<label>` (or `<legend>` when used inside a `<fieldset>`) to associate a textual description with a form control. It supports a `required` indicator, an optional adjacent description, several sizes and sentiments, and a disabled visual state.

## Summary

1. ✅ **Perceivable**: label/legend text provides high-contrast theme colors and the required indication uses a text symbol (`*`) rather than color alone. The label-to-control relationship is conveyed structurally when `htmlFor`/`legend` are used.
2. ✅ **Operable**: the component relies on native `<label>` semantics, so clicking it focuses the associated control; there is no custom keyboard handling to break.
3. ✅ **Understandable**: the label text is readable and provides an accessible name for the associated control; a descriptive label is the responsibility of the consumer.
4. ❌ **Robust**: the intended `aria-label="required"` on the required asterisk is not rendered (the `Text` component does not forward it), leaving the required indication unnamed and ambiguous for assistive technologies.

## ARIA Pattern

There is no dedicated WAI-ARIA Authoring Practices pattern for a form label; the component implements the native HTML `<label>`/`<legend>` element semantics and the [Radio Group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/) guidance for `legend` usage inside a `<fieldset>`. See also the [ARIA Authoring Practices - Providing Accessible Names guidance](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/).

## Rules

Enforced by the component:

- ✅ [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - The label is structurally associated to the control via the native `htmlFor` attribute when `as="label"`, and as a `<legend>` when `as="legend"`.
- ✅ [WCAG 1.4.1 - Use of Color (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) - The `required` state is conveyed with the text symbol `*` (not color alone), satisfying the requirement for a visible alternative to color.
- ✅ [WCAG 1.4.3 - Contrast (Minimum) (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) - Text colors and the danger `*` come from the theme sentiment palettes which satisfy contrast.
- ✅ [WCAG 4.1.2 - Name, Role, Value (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) - When `as="label"` and `htmlFor` is provided, the label text becomes the accessible name of the associated control. When `as="legend"`, it names the fieldset group.

To apply when using the component:

- [WCAG 2.4.6 - Headings and Labels (Level AA)](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html) - Provide a label text that clearly describes the associated control. When `required` is used inside an input component, also set `aria-required` on the actual form control so the required state is programmatically determinable.
- [WCAG 2.5.3 - Label in Name (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html) - Ensure the visible label text is part of the control's accessible name; do not pass an `aria-label` that omits the visible label text.
- [WCAG 3.3.2 - Labels or Instructions (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html) - Always use the component to label an input/legend, or the control will have no accessible name.
- [WCAG 1.3.1 - Info and Relationships (Level A)](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html) - When `as="legend"`, the component must be placed inside a `<fieldset>` (as done in `CheckboxGroup`, `SelectableCardGroup`, etc.) for the grouping relationship to be conveyed.

## Accessibility issues

**High:**

- Required indicator has no accessible label - The `*` marker is given `aria-label="required"` (`LabelContent.tsx:47`), but the `Text` component does not forward `aria-label` to the rendered element, so it is silently dropped. The snapshot confirms the `<span>` renders with no `aria-label`. As a result, screen readers announce the raw `*` character (e.g. "star" / "asterisk"), which is ambiguous and does not clearly convey "required". Fix by rendering the required indication so its name is actually emitted (e.g. an element with an effective label, or a visually hidden "required" text per RFC #6585), or forward the label through `Text`.

**Medium:**

- Required state not included in the accessible name of the associated control - When used with `htmlFor`, the `<label>` and the `*` are siblings within a `Stack`; the `*` is not part of the label element, and its own label is dropped. The control's accessible name is therefore only the plain label text with no required information. Prefer relying on `aria-required` on the control (consumer side) and/or adding a visually hidden "required" text so screen reader users receive the same required signal as sighted users.

**Low:**

- `disabled` is purely decorative - The `disabled` prop only changes the text appearance and cursor (`styles.css.ts`); it carries no semantics to assistive technologies. Since a `<label>` is not itself an interactive element, ensure the disabled state is also applied to the associated control.
- Pointer cursor on a `<legend>` with `htmlFor` - When `as="legend"` and `htmlFor` is provided, the `htmlFor` styling (`cursor: pointer`) is applied to the `<legend>`, which is misleading since `htmlFor` has no meaning on a legend.

## Dependencies

- **Text**: the `Text` component must be able to forward `aria-label` (or the `Label` component must stop passing it through `Text` and render the required indicator directly) for the required `*` to have an accessible name. Currently `Text` only forwards a fixed set of props and drops `aria-label`.
- **Input components** (`SelectInput`, `TextArea`, `NumberInput`, etc.): they consume the `required` prop of `Label`; they should propagate it as `aria-required` on the actual control so the required state is programmatically determinable (see [ARIA2](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA2)).
